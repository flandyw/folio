# AGENTS.md

Native Android notebook app. Single module `:app`, Kotlin + Jetpack Compose + Material 3. Package `com.folio.notes` under `app/src/main/java/com/folio/notes/`.

## Build / verify (JDK 25, compileSdk 36 / targetSdk 35 / minSdk 26)

- Toolchain: AGP 9.4.0 with built-in KGP 2.2.10; Compose compiler plugin `org.jetbrains.kotlin.plugin.compose` must match it. `jvmTarget` is intentionally unset (defaults from `compileOptions` Java 17).
- Canonical check (same as CI `.github/workflows/android.yml`):
  `./gradlew :app:assembleDebug :app:lintDebug`
- Windows-only shortcut: `.\build.ps1` (uses ignored `.tooling/` JDK/SDK; same default tasks). No `local.properties` / `.tooling/` needed on macOS/Linux with JDK 25 + SDK 36.
- Offline KaTeX check (also runs in CI): `node tools/katex-smoke.cjs`

## Architecture entrypoints

- `MainActivity.kt` → `FolioApp.kt` (nav, pickers, sharing, settings) → `FolioViewModel.kt` (library/editor state, lazy page loads, app-scope serialized save queue, survives Activity recreation). `WorkspaceScreen.kt` holds the split/reference companion pane; its PDF tools are pure maths in `PdfReference.kt` and the panels in `PdfReferencePane.kt`. Both workspace dialogs (document picker, pane options) live in `WorkspacePanels.kt` over the pure rules in `WorkspacePicker.kt`.
- Persistence: `NoteRepository.kt` (one fsynced journal append per batched transaction + background snapshot compaction) over pure codecs `InkBinary.kt` (on-disk binary pages/journal) / `NoteStore.kt` + `PageJournal.kt` (JSON: legacy pages, archives, edit logic) / `NotebookArchive.kt`. Rendering: `InkView.kt` (native input surface) + shared `InkRenderer.kt` (editor/thumbnails/exports). A finite page's committed ink raster (`CommittedInkCache.kt`) is built on a worker thread for 40+ strokes, started as soon as the view has a size, and parked in the process-wide `InkRasterStore` (64 MB, cleared on trim-memory) when the view leaves, so scrolling a dense page back in is one bitmap draw instead of a UI-thread rebuild. Infinite canvases still rasterize inline.
- The graph tool is dressing, not a special ink type: `GraphStyle.kt` (style + the single-stroke label font) and `GraphAxes.kt` turn a drag into ordinary `Tool.LINE` strokes, so `divisions`/`step`/origin changes cost no migration and never touch the storage format. The style lives in one preference string (`GraphStyle.PREF_KEY`) that the editor watches.
- Keep `PdfSearch.kt`, `PdfLinks.kt`, `PdfOutline.kt`, `NotebookTextSearch.kt`, `VceModels.kt`, and other `*pure*` helpers free of Android imports so they stay cheap to exercise from scratch or the REPL. `AccentTones.kt` is pure the same way: the user's accent colour only *re-tints* a scheme, so every role keeps the contrast it had (walk the lightness away from its `on…` colour until the original ratio is restored) — hue must never cost readability, and ink colours never change with the accent.
- Marking and feedback (`Marking.kt` pure, `MarkingPanel.kt`, `FolioViewModel.applyMarking`/`dropFlag`/`makeRoom`) builds comments, mark stamps, numbered flags and the `Feedback` sheet from ordinary text boxes and ink, so it needs no format change; make-room grows only non-PDF finite pages. Details in `docs/marking.md`.
- `mistakes/*` is ExamTrack review (Supabase sync + cache); `math/*` is reusable offline KaTeX. Details and smoke test in `docs/examtrack.md`.
- Writing follow is the same engine on a page and an infinite canvas, but a canvas has no printed line end and no absolute scale. Two rules keep it honest there: the writing lane is the **visible viewport** inset by the end margin (`FollowNavigation.infiniteRegion`, rebuilt per stroke), and the minimum-zoom gate becomes a legibility test in screen pixels (`FollowLegibility`), because a canvas zooms relative to whatever the view fits. `FollowPreferences.minimumZoom` therefore only applies to pages. Navigation on a canvas (pinch, pan, camera restore) suspends follow, so a viewport change never yanks the page mid-write. The pure parts (`WritingFollow.kt`, `WritingGuides.kt`, `FollowGlide.kt`) stay free of Android imports; `node tools/writing-follow-smoke.cjs` (CI) compiles and traces them. Details in `docs/writing-follow.md`.

## Storage format (do not reshape casually)

- Notebook dir `files/notebooks/<id>/`: `note.json` (title/folder/star/tags/attempts/redo flags + per-page summaries, **no ink**; checkpointed when the writer goes idle, never per stroke) + `pages/<id>.fps` (binary snapshot, `InkBinary.kt`: `FOLP` + version 1 + `journalSeq` + `revision` first so the sequence is readable from the first bytes, then strokes/texts/images/undo/redo, trailing CRC32; samples are raw float32, pressure omitted when uniformly 1) + `pages/<id>.fjl` (binary journal: one `[len][crc32][payload]` frame per `PageTransaction`, one append + one fsync per batch, folded into the snapshot past 4 MB while the writer is idle; a frame that is short or fails its CRC ends the log) + `images/*.jpg` + `source.pdf` if imported. `NoteMetaCodec.VERSION = 6`, `PageSnapshotBinary.VERSION = 1`, `JournalBinary.VERSION = 1`. **Nothing writes JSON pages any more.** A page still stored as `<id>.json` + `<id>.journal` (+ `<id>.history`) is converted on first open (`NoteRepository.convertLegacyLocked`): the binary snapshot is written with the journal replayed and undo stacks folded, read back and compared with the decoded JSON, and only then is the JSON deleted; a mismatch deletes the new file and fails the open, leaving the JSON untouched. A binary snapshot beside leftover JSON means an interrupted conversion, so the JSON is debris. Decoded strokes hold their samples in `PackedPoints` (one `FloatArray`, still a `List<InkPoint>`).
- New `.folio` and library backups use native v3 manifests (`NativeBackup.kt`): content-addressed index/snapshot/journal/image/PDF objects, compressed binary ink, and preserved undo/redo. Portable ZIPs contain every object; automatic restore points reference shared gzip/raw `.fbo` files in `Folio backup data` (`IncrementalBackup.kt`) and retain two points. v1 nested archives / v2 JSON library backups and old JSON `.folio` files remain readable; their imports still convert through `saveAll`. See `docs/backups.md` and `node tools/backup-smoke.cjs` (first run `./gradlew :app:prepareBackupSmoke`).
- Journal/snapshot invariant: a snapshot records the last journal sequence it contains **and** the undo/redo stacks as of that point, and each record states its own stack effect, so folding the log onto it rebuilds the same stacks before the log is dropped. Torn final journal line is discarded. On load a page's revision is `max(index, snapshot, journal)`.
- Page edits are positional, never whole-page: `StrokesEdit` is `Add`/`Remove`/`Insert`/`Replace`/`Rewrite`/`Set`, and `Set` only for migration or a page that shrank past half. `PageJournal.invert()` (not a second `diff`) produces the undo edit, because a diff would describe a page that grew in the middle as an append — an inverted edit must therefore undo back to the exact same page. `.folio` archives always expand to full portable pages. Folders in `files/library.json`; previews in `cacheDir/thumbnails`; mistake cache in `files/examtrack/<user-id>/cache.json` (v2).
- Layers are per page and live in the page *content*, not the index: `NotePage.layers` (bottom first; empty = one implicit base layer, so pages that never use layers are byte-identical to before) plus a `layer` int on every `Stroke`/`TextBox`/`PageImage`. They travel as a `layers` channel in `PageContent`/`PageEdit`, so layer edits ride the same journal and undo stacks as ink and stay atomic with moving items between layers. Binary: a stroke on a non-base layer sets flag bit 8 (+varint), an edit sets flag bit 8 (+JSON list), and a snapshot with layers is written as `PageSnapshotBinary` version 2 (version 1 otherwise; both read). An older build cannot read a page that uses layers. `PageLayers.kt` is the pure rule set; `InkRenderer.page/overlay/exportPage` and `InkView` draw `PageLayers.view(page)` (hidden dropped, layer order), and hidden/locked layers are untouchable by eraser, lasso and tap-select. Layer order orders ink among ink and text among text; pictures and text still draw in their usual stacking relative to each other.
- Undo is two stacks merged by sequence number in `FolioViewModel.undo/redo`: the per-page ink stacks (persisted) and an in-memory per-session `StructureStep` stack for page add/insert/duplicate/delete/move and page paper/title/bookmark/redo-flag. A page removed by an undo (or a delete) is held whole in the step closure, so the step list is capped (`MAX_STRUCTURE_UNDO`).
- The peek view is one `Notebook.peekAnchor` (page id + page-unit rect) at the top level of `note.json` / `.folio`; older files stored it on a page, which `PeekAnchor.decodeNotebook` still reads. Adding it did not bump `NoteMetaCodec.VERSION` on purpose — an older app would refuse a newer index outright.
- Mistake practice pages are always infinite canvases, so `AppPrefs.MISTAKE_PAPER` only picks the printed guide behind them (every `Paper` renders on a canvas; `PLAIN` is no guide). Changing it never touches an existing page.
- There are no unit or instrumented tests in this repo. Any change to the storage format or the journal/snapshot invariant must be verified by opening the affected notebooks on a device before release, and the shape of that manual check is documented in `docs/examtrack.md` / `docs/sync.md`.

## Conventions / gotchas

- Material 3 pinned to `1.5.0-alpha01` with Compose BOM `2025.06.01`. Stable M3 omits Expressive APIs (`ExperimentalMaterial3ExpressiveApi`); check Android M3 release notes before upgrading. Reference: `ExpressiveComponents.kt` previews.
- `app/build.gradle.kts` `lint { disable OldTargetApi, GradleDependency, TrustAllX509TrustManager }` — the TrustAll warning is a third-party TLS jar in Gradle cache, not Folio code. `AutoboxingStateCreation` is informational-only.
- Release builds run R8 + resource shrinking (`app/proguard-rules.pro`; pdfbox-android is kept whole because it loads font tables reflectively) and package only arm64-v8a/armeabi-v7a (the OCR library's x86 natives were ~23 MB). Smoke-test PDF import/search, OCR, sync and update install on a device after changing dependencies or keep rules.
- Shrinking/renaming storage fields requires migration plus a manual round-trip check on device (see `docs/examtrack.md`); scheduler parity is regenerated by porting the ExamTrack cases by hand.
- A notebook's `cover` is a packed int: the low byte is the colour **index**, the next byte is the `CoverStyle` design (`CoverStyle.kt`, pure; `CoverArt.kt` draws it, `CoverPicker.kt` picks it). Old covers have design 0, so they wear the default design in their old colour and nothing migrates; an unknown design falls back to 0. Custom covers are appended after `BuiltInCoverColors`, so existing notebooks keep their colour. Never grow `BuiltInCoverColors` (that shifts every custom colour); extra ready-made colours go in `SuggestedCoverColors`, which Settings copies into the user's list. Removing a colour from the middle of a user's list therefore shifts the ones after it: only offer removal that keeps saved covers meaningful, and verify a cover round-trip on device after changing the cover list. New preferences go in `AppPrefs` with a default and a clamping helper.
- `postgrest.rpc` params must be typed `Map<String, JsonElement>` (see the builders in `sync/SyncRemote.kt`): a map inferred as `Map<String, Any>` has no kotlinx serializer and throws `SerializationException: Serializer for class 'Any' is not found` before the request is sent, which surfaces as a sync error and silently never publishes queued work. Sync errors name Focal, not the merged-away ExamTrack project, and the banner keys off `isSyncTrouble(status)` rather than the wording.

## Secrets / releases (never commit real keys)

- ExamTrack config order: env → `-P` gradle property → untracked `local.properties` → safe placeholders. Requires HTTPS URL + `sb_publishable_` or `anon`-role JWT; secret keys fail the build. CI greps `app/build.gradle.kts docs/ README.md .github/` for real `sb_publishable_*` / `*.supabase.co` and fails. ExamTrack was merged into Focal, so there is one credential pair: `FOCAL_SUPABASE_URL` / `FOCAL_SUPABASE_PUBLISHABLE_KEY`. `FocalSupabaseConnection` is the process-wide Supabase client (Auth/Postgrest/Realtime/Storage) shared by `FocalStudyManager` and `ExamTrackAuthRepository`; never build a second client on the same session file.
- Releases (`.github/workflows/release.yml`): Gradle maps full `git rev-list --count HEAD` to display version `x.y.z` (`x=count/100`, `y=(count/10)%10`, `z=count%10`). Stable Android `versionCode` is `count*10000`; experimental builds reserve offsets 1..9999 with `build.sh` / `tools/next-experimental-build.py`, persist the high-water code in ignored `.tooling/experimental-version.json`, and display `X.Y.Z-exp.N`. The allocator also reads the last release APK's metadata and the VPS's latest manifest, so losing the local counter does not reuse a delivered code. Failed builds consume their reserved number. `build.sh` serializes build/publish and passes `-PfolioExperimentalBuild=N` plus the expected commit count; ordinary Gradle/CI builds are stable. Keep `main` append-only so the next stable commit supersedes the preceding experimental block. Stable tags remain `vX.Y.Z`, and releases ship `update.json` (schema 1, actual APK version code/name/tag) alongside the APK and `SHA256SUMS`; only historical GitHub releases without that asset use the old commit-count / `v0.2.N` tag mapping. Signed RSA-3072 (`folio` alias) via `ANDROID_KEYSTORE_BASE64/PASSWORD` secrets; local signed builds need `ANDROID_KEYSTORE_PATH/PASSWORD`, else `assembleRelease` fails. Each release verifies with `apksigner`. Debug and release keys differ — uninstall debug (export first) before installing a release.
