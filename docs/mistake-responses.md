# Mistake responses

The review offers **Write**, **Type** and **Paper** in the top-right app bar, immediately before the three-dot menu, leaving the response area its full height. On narrow windows or with large system fonts the switch uses icons with accessibility labels; previous attempts and the revealed card's Skip action move into the menu. Write remains the default; an explicit choice is remembered on this device. An unfinished typed answer reopens in Type. Switching modes keeps both the handwriting and the typed response.

The review uses one uniform theme surface for the top bar, question pane and heading, pane divider, response toolbar and viewport, and footer. Corrections and explanations are plain text on that same background. The embedded response editor inherits a local colour scheme with its surface tiers set to the review background, so its toolbar does not introduce a separate band. The notebook's writing paper keeps its own colour.

Type is a sheet of paper (a borderless multiline field on the lowest surface, outlined in the accent colour while focused) with normal keyboard selection, paste and editing. The empty sheet explains `$…$` maths. It saves each text change through `FolioViewModel.commitText` and the existing serialized document writer; the footer shows *Saves as you type* / *Saving…* / *Saved · N words*, or *Not saved* with Retry save. Comparison dismisses the keyboard, reveals the correction and shows the answer typeset (Preview) beside it once; Edit returns to the field. Rating waits for the writer; a failed save prevents rating. Space, S and number shortcuts do not trigger review actions while the answer field has focus; in the field, Ctrl/⌘+Enter compares and Esc finishes typing.

While the field is focused a row of keys sits above the keyboard (pure `TypingBar` in `MistakeTypedResponse.kt`): **Maths** inserts `$…$` around the caret or selection (inside maths it becomes *Leave maths* and steps past the closing `$`), a list key toggles `- ` on the line, and symbol keys (powers, subscripts, fractions, roots, π, θ, ±, ×, ÷, ≤, ≥, ≠, ≈, →, °, ∞) insert Unicode in prose and LaTeX inside maths; a power key after `x` makes `$x^{}$`. Enter continues `- ` and `1.` lists, and Enter on an empty item ends the list. The Write / Type switch shows a dot on the other mode when it holds working.

On narrow windows the question folds down while the software keyboard is open, and the confidence chips leave room for Done typing and Compare answer. Expanded windows keep the question beside the response. Very short windows temporarily hide the response toolbar and question pane to preserve an editable area. Done typing restores the normal layout. Merely opening a card in Type does not summon the keyboard; choosing Type or tapping the field does.

Preview renders formatted text and offline maths through the same rich-text renderer as the question. Sharing a typed-only answer sends the question and answer as text. Mixed working retains the existing picture/clipboard sharing path. Previous attempts show typed answers as readable text, alongside any handwritten working. The device storage tab is labelled Responses and includes both modes.

There is no notebook or sync format change. Each review's answer is an ordinary `TextBox` on its existing practice page, identified by `mistake-response-<reviewId>`. A new response sits to the right of existing working and uses an editable layer; existing placement, style and layers are preserved. Drafts and completed working stay on this device and travel in notebook backups, just like handwriting. Only ratings use the existing Focal review sync.

The review observes its practice page through `DocumentReader.observePage` and requests loading independently of the Write editor. The shell's page metadata always has `loaded = false` and no content; it must not drive Type's loading state, response restoration, working indicators or sharing.

## Verification

`MistakeTypedResponseTest` checks the practice-page reader's loading and answer updates while shell metadata stays unloaded, typing keys, list continuation, mixed ink/text snapshot round-trip and undo, independent review identities, canvas edits, layer choice, and retention of typed-only attempts. Existing scheduling and writer tests cover rating persistence and save failures.

On a device, test a narrow portrait window, landscape with a software keyboard, a wide tablet and split screen. Type several paragraphs, move the caret, paste, compose accented text, and scroll to the last line. Type spaces, S and 1–4 before and after revealing: they must stay in the answer. Switch Write → Type → Write, skip and resume, leave and return, rotate, restart, then rate immediately after an edit. Confirm both kinds of working survive in previous attempts and a backup round-trip. Check math preview, typed and mixed sharing, and Retry save after a storage failure. Test large system fonts and TalkBack, including the response switch and answer field.

## Exam paper

The third mode, **Paper**, prints the question on a white exam sheet (`MistakeExamPaper.kt`): subject/paper line, bold *Question (N marks)* header, the question in a serif face, its pictures, then ruled answer lines (about three a mark, 4–30; *+* / *−* in its toolbar adds or removes lines, remembered per question on this device). It replaces the question/response split. Settings › Mistakes › Answering picks the mode a new question opens in; switching during a review changes the same preference.

The sheet is Compose laid out at a fixed width in page units (`ExamSheet.WIDTH`) and drawn under a transparent `InkView` (`InkView.paperless`) bound to the same practice page as Write, through the same `pageMutations`, undo and journal. The sheet follows the view's infinite-canvas camera, so fingers scroll and pinch the paper and ink together. The first answer line's top is page y = 0: answers never move off their lines, and highlighter marks on the question sit at negative y. A question picture's width and its aspect ratio are stored on this device (`mistake.exam.image*`), so its space is reserved before the file loads. Releasing a picture resize runs pure `ExamSheet.reflow` as one stroke edit (one undo step): ink above the picture moves with the text there and ink on the picture scales with it, so highlights stay on their words; undo reverts the ink but not the picture's size. Ink written in Write mode shows on the sheet at the same page position, and vice versa.

The toolbar is the notebook screen's bar: `ExamTopBar` (beside `EditorTopBar` in `FolioToolbar.kt`) uses the same `EditorBar`, dock buttons, centred tool strip and narrow-pane folding, and hosts the editor's flat `FloatingInkToolbar` driven by the editor's `EditorToolState` over the shared `ink-tools` settings. The strip keeps pen, shapes, highlighter and eraser (`ExamSheet.SLOTS`; every other slot is hidden) with the editor's quick colours, widths, brushes, tool settings popover, presets for those tools, ink options bar and Behaviour menu. The bar's left side holds add/remove lines, resize pictures and fit instead of pages, find, layers and add page; the right holds the question clock (in the menu when the bar is narrow), share (hold for the question text) and a menu. The clock counts against exam pace (1.5 minutes a mark) and stops at Compare. The bar sits on the review's surface, as the embedded editor does in Write mode, so the header is one band; the desk below is `surfaceDim` (black under dark paper). The header shows the marks, so a trailing "(N marks)" in the question text is dropped (`ExamSheet.questionBody`). Compare appends a *Marking guide* below the lines and scrolls to it. No storage format change. The sheet lays out at its own density; `KaTeXWebView.render`/`renderDocument` scale requests to the WebView's real pixel ratio so maths documents fill that layout (cache `katex-…-document-v5`).

The ink view takes the editor's input settings through `rememberEditorPreferences`: scribble to erase (and hold to erase), eraser pressure, whole-stroke and single-stroke eraser, shape assist, snapping, measurements and graph style, two-/three-finger tap undo/redo, palm-rejection grace, fast pan, maximum zoom and pen-start tool borrowing. The pen's button / double-tap runs the configured stylus shortcut where it maps to a sheet tool (pen ↔ eraser, previous tool, pen ↔ highlighter, undo, colour palette; lasso and next line do nothing), with the same haptic pulse; pen haptics and writing feedback start and stop as in the editor.

In a dark theme (Android 12+) the sheet and its ink are drawn through one colour matrix (`ExamSheet.nightMatrix`: lightness inverted, hue kept, white paper to #242424 on a black desk, no shadow), so pen ink is light and highlights keep their colour family; the low-latency front buffer is off there (`InkView.frontBuffer`) because it cannot be filtered. Stored ink and shared pictures are unchanged: sharing still sends the white sheet.

The sheet lays out at its own density, so `KaTeXWebView.render` / `renderDocument` scale each request to the WebView's real pixel ratio; otherwise a maths question filled only part of its width at a smaller size (disk cache `katex-…-document-v5`)., rotate, leave and return (ink stays on the same lines and words), resize a picture, add lines, switch Paper → Write → Paper, undo/redo, two-finger scroll and pinch, finger drawing on and off, dark theme (ink, highlights and pictures on dark paper; sharing still white), stylus double-tap, scribble to erase, single-stroke eraser, two-finger undo.

## Recording practice in Study

**Record in Study timer** is enabled by default and remembered on this device. Change it on Mistakes → Today or with the timer toggle beside Write / Type. Starting a due card uses the same subject filter, order and session length as Start questions, with the chosen card first; the remaining cards follow automatically. This also applies when practising a due card from its details or resuming its response.

One practice queue owns one Study session. Each question visit is a timer interval; skipping, rating or leaving closes it. Backgrounding or disabling recording closes the current interval, and returning or enabling it resumes in a new interval without counting the gap. Write / Type changes keep the same interval. Finishing or leaving the queue completes the session. Recording pauses another running study timer so the same time is not counted twice.

Sessions carry a Mistake practice title, exam/paper/question descriptions, and the matching built-in or custom subject ID. Mixed queues have no single session subject; every interval retains its question and subject in integration metadata. Existing Focal rules still apply, including merging nearby completed sessions shorter than two minutes and pruning duplicate overlapping intervals. Local timer intervals and metadata are saved through the Study manager and replay offline through its normal lifecycle commands. Five-second checkpoints finish an interrupted visit at its last saved instant after process restart. Practice notebooks and review scheduling are unchanged.

Device checks: start a middle Today card with a short session limit, then rate through the queue in both Write and Type. Check one Study session with the expected intervals, total duration, subject, title and description; repeat with custom and mixed subjects. Toggle recording in both places, skip and return to a question, leave a partial queue, background/resume, rotate, and kill/reopen offline before reconnecting to Focal. Check gaps are excluded, earlier work survives, and an existing Study timer is paused when recording starts.
