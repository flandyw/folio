# Folio architecture and reliability audit

Scope: one Android app process, stylus input at display rate, large notebooks with lazily loaded pages, background saves/backups, and optional Focal sync. This is a source audit, not a tablet UX or latency measurement.

## Architecture and critical flows

- Launch: `MainActivity` handles shared PDFs and input routing; `FolioApp` owns navigation, pickers and sharing. `FolioApplication` owns the runtime across screen lifetimes. Feature ViewModels expose shared state rather than maintaining independent document copies.
- Write: `EditorScreen` / `EditorSession` / `ContinuousDocumentHost` host `InkView`. Palm rejection precedes tool dispatch. `DocumentEngine` plans edits and history; `DocumentStateStore` publishes immutable state. `DocumentWriteCoordinator` serializes writes and retries. `NoteRepository` appends journals and folds them into snapshots while idle. Grouped edits use a recoverable intent and ledger.
- Reopen: notebook indexes contain page summaries. Loading reads snapshots plus journals, merges content into current metadata, then exposes the page. Revision numbers key caches and reject stale operations; recovered revisions must never fall backwards.
- Find/export: search and annotated-page selection fetch unopened pages through `pagesForSearch`. Typed search reads text; OCR reads page and sticky ink and caches by revision. PDF preservation imports source pages and overlays Folio annotations; raster export draws complete pages. PNG has a separate bounded bitmap path.
- Import/restore: picker or VCAA downloads enter `BackupService`, then repository staging and validation. Native backups verify hashes before installation; legacy portable archives decode JSON and assets. Restores allocate fresh notebook identities.
- Delete/recover: catalog operations queue after saves; Trash renames whole notebook directories and offers restore. Permanent deletion detaches a directory before recursive cleanup.
- Backup: manual exports wait for saved changes. OS jobs capture files under the application storage gate, then release it before slow SAF writes. Incremental objects are content addressed.
- Account/study: one Supabase connection and session lifecycle serve mistake review and study/planner sync. Local caches and queued operations retain offline work; account exchanges and refresh are serialized.

## Implemented findings

1. Page loading discarded a newer journal revision when merging content with current organization. The shared merge now retains the maximum revision while keeping the current title, dimensions and flags.
2. Search loading removed strokes and images from unopened pages. OCR could cache an empty answer and export's Annotated selector missed ink-only pages. Loading now preserves content; OCR cache version 2 rejects previously incomplete entries. Regression tests cover partial read failure and cancellation.
3. Typed search lowercased complete strings before calculating snippet offsets. Unicode lowercase expansion (for example repeated `İ`) could move the match beyond the original string and crash search. Matching now uses case-insensitive original-string offsets.
4. PDF overlay detection ignored blank sticky notes, including notes with handwriting. Sticky paper now counts as an annotation even without typed words.
5. PDF bitmap scaling applied a minimum of 0.5 after its maximum-dimension cap. A 100,000-unit canvas could allocate a 50,000-pixel side. Both PDF exporters now share a bounded scale rule, with tests for large canvases, narrow pages and invalid dimensions.
6. Legacy `.folio` loading retained every PDF/image in memory and skipped unknown ZIP entries without a work bound. Assets now stream into caller-owned staging files; all entries share a 512 MiB decompression budget and a 10,000-entry limit. Per-file limits remain, failed/cancelled extraction removes staged files, and single-notebook and nested v1 library imports use the same reader. `NotebookArchiveTest` covers compatibility, malformed/duplicate entries, byte/count limits, cancellation and staging ownership.
7. Legacy library restore tried to delete installed notebooks from an already cancelled coroutine, so cleanup could be skipped. Both legacy and native restore now share non-cancellable rollback through repository deletion, including cache cleanup. A failed deletion does not skip later notebooks or hide the original error. `LibraryRestoreTest` interrupts after zero through three installs, waits on a storage lock, keeps existing notebooks untouched, and checks cleanup failures.
8. A failed preserved-PDF overlay left its imported page in place and fell back to a raster page without the source background, duplicating or blanking the question. The partial page is now removed first, the fallback draws the source background at the page's aspect ratio, cancellation skips the fallback, and export bitmaps are recycled on asset failures. `PreservedPdfFallbackTest` covers rollback, cancellation, fallback failure and a saved-PDF round trip; source-background pixels still need a device check.

No notebook format, journal record, dependency or account protocol changes.

## Ranked remaining backlog

1. **Search memory and responsiveness (medium).** Correct OCR/annotation selection now retains full loaded page content in the search snapshot. Long notebooks should index sequentially and retain compact search results/annotation flags instead. Measure representative notebooks before selecting a memory budget; avoid restoring the lossy projection.
2. **PDF rendering resource failure tests (medium).** Several render helpers allocate a bitmap before loading assets, outside their cleanup blocks. Inject missing/corrupt assets and cancellation to verify bitmaps, PDF descriptors and temporary files are released.

No deletion candidates were established: the compatibility archive writers still serve fixtures, and runtime forwarding methods still have callers. No speculative dead-code removal was made.


The standalone changed-rule checks, `node tools/katex-smoke.cjs` and `node tools/backup-smoke.cjs` also passed. The larger compiler heap was a command-line override only; no project settings changed.

No device was connected. Native ink latency, real bitmap appearance, filesystem power-loss behavior, live account sync and accessibility interactions require device checks. Signed APK verification/publication requires local signing files absent from this worktree; no release was published.
